## 1. 网站 【定】

- **技术**：three.js + Vite + JavaScript，和 flocks 同一套
- **部署**：静态网站，放 Vercel，发链接即可
- **不用数据库**：上传的文件直接在浏览器里读取和计算，不经过服务器、不存储

### 两个视角
- **全局视角**：像 flocks 看鱼缸那样绕着房子转，看烟在各个房间的分布、从哪扇门漫过去
- **人的视角**：一个人眼高度（约 1.6 米）的摄像头。烟层降到眼睛以下时视野变暗，这一刻最能体现「真实发生时看起来是什么样」

### 上传什么 【待定】
一个普通的三维模型只有一堆面，不会告诉引擎哪里是房间、哪里是门、门楣多高，而区域模型恰恰需要这些。所以网站可能要接收两样东西：

- **房间结构**（给引擎用，必需）：有哪些房间、怎么相连、门的位置和门楣高度
  - 【待定】形式：一个简单的数据文件，或者网页上的小编辑器（在平面图上画墙、点门）
- **三维模型**（给画面用，可选）：Aholo 生成的家具和场景，让画面更真实；家具也可以作为燃料

从任意三维模型自动推断出「房间和门」是研究级难题，演示阶段不碰。

## 2. 烟引擎 【定：Billy 做】

- 【建议】用 JavaScript 写成**不依赖画面的独立模块**，可以单独测试。网站直接用；到 AR 阶段，iOS 可以通过苹果自带的 JavaScriptCore 运行同一份代码，不用重写
- 【建议】**区域模型**：每个房间是一个节点，门窗是连接。每个房间只算烟层高度、温度、浓度几个量，实时运行没有压力。烟能否进入下一个房间，取决于烟层是否降到门楣以下
  - 擅长住宅这种「小房间 + 门」的结构
  - 不管房间内部细节；长走廊、大空间不适用
  - 房间内部的翻卷质感由画面层补上：整体演化靠物理，局部质感靠画
- 不用 FDS：太慢（几小时到几天），不是为实时设计的
- 【建议】演示版的房间数据：一个三个人共享的**理想房间模型**

## 3. Aholo（群核）【定：比赛必须使用 Aholo Lux3D】

| 工具 | 是什么 | 是否必须 |
|---|---|---|
| **Aholo Lux3D** | 上传图片或文字，生成可预览、可编辑的 3D 模型；有标准版和极速版 | **必须** |
| Aholo API | 3D 物体生成、世界生成、云端渲染、重建 | 可选 |
| LuxReal | AI 视频生成 | 可选 |

**输出类型选网格模型，不选 3D 高斯。** 3D 高斯是一团半透明的点，没有明确的表面和体积，做不了遮挡和碰撞；网格模型有表面，可以算包围盒，能和烟、墙互动。对区域模型来说，家具只需要三样信息：是什么（决定烧起来多猛）、在哪、大概多大。

可能的用法：
- 【建议】**家具模型**：拍照生成沙发、桌子等，放进房间，既是画面也是燃料
- 【待确认】**训练数据**：用 Aholo 生成大量门窗、家具模型，从不同角度渲染成图片，作为泽昊识别模型的训练数据
- 【待查】API 的「重建」「世界生成」能不能从照片直接生成房间
- 【建议】LuxReal 做路演视频

## 5. 第二阶段：AR

### 平台：Swift 原生 iOS + ARKit 【定】

**ARKit 是什么：** 苹果内置在 iPhone / iPad 里的 AR 开发框架。它用摄像头和运动传感器实时计算手机在空间里的位置和朝向，并识别周围的平面，App 在此基础上把虚拟内容「放」进真实空间。

**为什么不是别的：**

| 方案 | 结论 | 原因 |
|---|---|---|
| 网页 WebXR | 不用于 AR | iPhone 的 Safari 不支持网页 AR 模式，只能原地转动，不能走着看 |
| 网页 + 贴标记 | 不用 | 体验打折太多 |
| Unity | 不用 | 要学 C#，iOS 远程分发同样要付费 |
| 微信小程序 | 不用 | 不考虑 |

### 开发环境 【已就绪，2026-10-23】
- Xcode 27.1，iOS 27.1 开发包，许可协议已同意
- Apple 账号已登录（免费账号）
- iPhone 15 Plus 已配对，开发者模式已开

### iPhone 15 Plus 上 ARKit 的能力
15 Plus 没有 LiDAR，RoomPlan 和深度网格用不了，但墙来自图纸，不依赖这些。

| 能力 | 用处 |
|---|---|
| 世界追踪（6DoF） | 人在家里走，烟留在原地 |
| 平面检测 + 分类 | 识别墙、地面、天花板，还有门和窗 |
| 射线检测 | 把画面里的门放到三维的墙上 |
| 每一帧摄像头画面 | 接入识别模型 |
| 人体遮挡 | 人站在烟前面时挡住烟 |
| 空间地图保存 / 重新定位 | 图纸对齐一次后保存，下次自动对上 |

### 门窗识别
- 【建议】先用 ARKit 自带的平面分类
- 已知局限：关着的门可能认得出，**开着的门是一个洞，很可能认不出**；不知道开关状态；准确率未实测
- 【建议】红胶带作为保底
- 【建议】泽昊的模型接入方式：他交付 PyTorch / ONNX 模型 + 参考脚本 + 测试图片和期望结果；Billy 在 Mac 上用 coremltools 转成 Core ML 并核对结果

### 户型和对齐
- 演示在 Billy 家里录，户型用卷尺量（长宽、层高、门的位置宽度和门楣高度、窗的位置高度）
- 【建议】手动点两个墙角对齐图纸，用空间地图保存

4. **AR 阶段**：门窗识别效果未实测；Swift 和 ARKit 都是新的
