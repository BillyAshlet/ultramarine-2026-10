# A 物体卡：做完了（2026-11-09）

## 做了什么

- **`duplex-fire/src/card.js`（新）**，是唯一的文件。卡片的样式也写在它里面，由它插进页面，所以没有改 index.html。**main.js 也没改**：world 会自动加载 card.js，点选写在 card.js 自己里面。
- **点选：** 单击任何物体，就会出卡片。做法和 doors.js 一样，只测物体，不测墙，所以隔着半透明的墙也能点到。下面这些点不到：在楼层剖切面以上的东西；图层被关掉的东西（比如燃气管线的勾去掉以后，燃气管就点不到）。
  - 家具、设备、管子按它们自己的网格来测。管子画得比实际粗（pipes.js），点选范围也跟着放大。
  - 门用 doors.js 画出来的门洞和门扇来测。
  - 窗没有单独的网格，按包围盒来测，厚度放宽到 20 cm。
  - 鼠标移上去，物体外面出现淡黄框；点开以后变成橙框。
  - 点空白处、按 Esc 或点 ×，卡片关掉。
  - 放火模式下点击归放火用，不出卡片。拖动视角也不算点击。
- **卡片内容（`cardFor`）：**
  - 名称、类别、房间、参考的是哪次实验。
  - `materials.json` 里这种材料的**每一个数**，每个数后面有编号，编号对应卡片底部的来源列表。来源以「假设」开头或带「[估]」的，数后面会有黄色小标签。写「as sofa」「as queen」的来源，会接着显示它指向的那条原文来源。
  - 「这一件的热量」：取物体表的 `fuelMJ`。木柜和 King 床的这个数是按长度或面积缩放算出来的，会标「估」，并写明怎么算的。
  - 有逐点曲线的材料（沙发、Queen 床），卡片里画出实测热释放曲线；物体在烧的时候，曲线上有一个圆点，表示「这一件现在烧到哪了」（燃烧时间、此刻的热释放）。
  - BIM 原名、IFC 类型、编号。
- **实时行（每帧刷新）：** 状态一直显示。下面这几行只在有值的时候出现：
  - 「现在」：此刻的热释放（`hrr`）
  - 「已烧」：从点燃到现在的时间
  - 「已烧掉」：已烧掉多少 MJ、总共多少 MJ
  - 「受热」：表面热流（`flux`）
  - 「落水」：落在它上面的水（`wet`）
- **给 G 用的面板：**
  - 调用方法：`import { showCard, hideCard } from './card.js'`，也可以用 `world.showCard`。
  - 接口和开工顺序里写的一样：`showCard({ title, rows, live, sources, image })`，另外多了几个可选项：
    - `rows` 每行可以写第三项「来源」，会自动编号、自动打「假设 / 估」标签。
    - `live` 的取值函数返回 null 时，这一行先隐藏。
    - 可选的 `subtitle`、`note`、`chart`、`onHide`。
- **控制台：** `duplexFire.world.card.open('e153')` 打开某件物体的卡片；`duplexFire.world.card.cardFor(物体)` 返回卡片内容但不显示。

## 检查了什么

1. **每种材料各取一件，卡片上的数和 `materials.json` 逐个比对**。13 种材料都比了，在页面里用脚本把卡片上的值换算回原单位再比较：

   | 材料 | 物体 | 结果 |
   |---|---|---|
   | sofa | e153 | 10 个数全对，来源一致 |
   | bed_queen | e163 | 10 个数全对 |
   | bed_king | e164 | 8 个数全对；峰值和总热量写成「缩放自 Queen × 1.31」 |
   | cabinet_run | e131 | 9 个数全对（按每米给的数） |
   | wardrobe | e123 | 9 个数全对 |

   | countertop / door_wood / window / gas_pipe / water_pipe / drain_pipe / appliance | e135 / e197 / e91 / e563 / e414 / e362 / e642 | 「可燃」和它的来源都对 |

2. **每类各点一件（模拟真的鼠标点击）都能出对的卡片**：窗 e91、木柜 e123、台面 e135、软垫 e153、桌子 e155、门 e197、排水管 e362、水管 e425、燃气管 e569、设备 e643。只显示一层（或二层）时点物体中心。两层都显示时，从上往下点，会先点到二层的东西，这是对的：点到的是离眼睛最近的那件。
3. **关掉燃气图层**以后，燃气管点不到；打开以后又能点到。
4. **放火模式下点击**：火放到了 B102，没有出卡片；退出放火模式后再点，出了卡片。
5. **实时行**：现在还没有 B，所以我在控制台手动设了 `state='燃烧'`、`ignitedAt`，再让 `hrr` 跟着沙发实测曲线变。结果「现在 463.9 → 471.5 → 485.2 → 497.2 kW」逐帧变化，曲线上的圆点也在动。这只是测试，**代码里没有写任何假数据**。
6. **G 的用法**：用 `import { showCard }` 显示了一张假的「轰燃」卡：来源自动编号，「假设」标签正常，live 行正常。

## 假设和要注意的

- **卡片上的数和来源原样来自 `materials.json`**，卡片自己不定任何数。唯一换算的是单位（W→kW/MW、J→MJ、s→min），保留 4 位有效数字。
- **「到峰值」「曲线」都是从小火点燃开始计时的实验数据**。这一点 materials.json 的来源里已经写明，卡片照原文显示。
- **曲线上的圆点画的是「这一件」此刻的值**，位置按物体的点燃时间算。如果 B 的燃烧曲线和实测曲线形状不同，圆点会偏离实测线。这是有意的：能一眼看出模拟和实验差多少。
- **实时行用 requestAnimationFrame 刷新**，不靠 world 的步进，所以暂停时也能看卡片。浏览器标签页隐藏时它会停，和主循环一样。
- **放火模式是从 DOM 判断的**：看「火放一层 / 二层」按钮有没有亮。如果 main.js 以后改了这两个按钮，这里要跟着改。
- **窗按包围盒来点**：world.view 里没有建筑图层的单个构件网格，所以用包围盒。

## 需要别人知道的

- **B：** 「现在」那一行读 `hrr`（W）、`state`、`ignitedAt`、`burnedMJ`，B 写这些就会自动显示。如果 B 给 materials.json 加了新的字段（带 `value` 和 `source`），卡片也会自动显示，标签用字段名。
