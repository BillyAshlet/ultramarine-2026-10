# T0 骨架：做完了（2026-11-09）

**其他任务现在可以接上。** 接口以 `开工顺序.md`「接口」一节为准，那一节已改成代码实际的样子。

## 做了什么

- **`world.js`：** 模块按文件名自动加载，不用改 main.js；每一步分五个阶段（`act` `source` 求解器 `transfer` `react` `report`）；一个模块出错只停它自己；`world.ignite` 的临时版本（B 替换）。
- **`objects.js`：** 从 BIM 数据建物体表，670 个物体，每个有类别、材料、房间、贴着它的空气格子、表面积、总热量和会变的状态。
- **`events.js`：** `emit`、`on`、`log`。没有 G 时打印在控制台。
- **`materials.json`：** 13 种材料，每个数带来源或标「假设 / [估]」。
- **`mac3d.js`：** 加了 `addScalar(name)`，燃气和水可以登记成随气流走的量。
- **`main.js`：** 建物体表和 world，`fire.step()` 换成 `world.step()`，重放起火点时 `world.reset()`，控制台有 `duplexFire.world` 和 `duplexFire.objects`。

## 假设和要注意的

- **物体编号：** 用的是 `e` 加它在 meta.json 里的序号，因为 meta 里没有 GlobalId。重新转换 BIM 数据会改变编号。
- **模型里没有燃气表、调压器**，燃气层只有管子和弯头（D）。
- **埋在墙里或楼板里的构件：** 有 120 根排水管、255 根水管、12 根燃气管、40 个设备，它们旁边半格内没有空气格子，所以改用一格半内的空气（`wallAir: true`）。其中 53、40、8、4 个连一格半内也没有空气，多半在地下或屋顶夹层（D、E）。
- **数据来源：** 沙发和 Queen 床的逐点曲线、点燃参数、柜子和茶几的估算，都来自另一个会话（fork-4-2「触电 联动」）写的 `家具着火数据.md`。T0 照抄过来、标了出处，没有复核原始 CSV。
- **床默认用床垫 C（铺床品，4.6 MW）。** 架构里原来写的是床垫 B（3.4 MW），换成 C 是因为 C 有逐点曲线。
- **高柜按 NBS 衣柜第 61 次实验（1349 MJ）。** 那次的衣柜里装了衣物，Duplex 的高柜装没装东西不知道。
- **茶几没有峰值数据**（`peakHRR: null`），由 B 来定并标「假设」。
